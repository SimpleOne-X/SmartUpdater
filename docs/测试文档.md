# 测试文档

怎么验证这个项目没问题：先看下面这张表，照着跑命令、对照"通过标志"就行。

## 1. 一眼看懂：跑什么、看到什么算通过

在项目根目录打开 PowerShell，按需要选：

| 想验证 | 命令 | 通过标志 |
|---|---|---|
| **代码和逻辑没问题**（日常只跑这个） | `dotnet build -c Release --no-incremental`<br>`dotnet test -c Release --no-build` | 构建 `0 个警告 0 个错误`；4 个测试程序集都是 `失败: 0，已跳过: 0` |
| **真实升级能走通**（真进程 + 真窗口） | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\e2e\run-e2e.ps1` | 每个场景一行 `PASS …`，退出码 0 |
| **AOT 原生发布没问题** | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\aot-smoke\run-aot-smoke.ps1 -RepoRoot .` | 最后一行 `PASS: native AOT publish succeeded …`，程序输出 `AOT-SMOKE OK` |
| **NuGet 包里没有 .exe** | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\pack-check\check-no-executables.ps1 -RepoRoot .` | `PASS: no .exe inside SimpleOneX.SmartUpdater.<版本>.nupkg` |

发版或演示前，**四个都跑一遍**。

## 2. 环境要求

| 项 | 要求 |
|---|---|
| SDK | .NET SDK 10（`dotnet --version` 能看到 10.x） |
| Shell | Windows PowerShell 5.1（端到端脚本按 5.1 语法编写） |
| 桌面 | 端到端脚本要弹出真实窗口并截图，需要桌面会话，**运行期间不要锁屏、不要手动点击示例窗口** |
| AOT 冒烟 | 装有 Visual Studio（含"使用 C++ 的桌面开发"工作负载）；脚本会自己处理 `vswhere` 的路径 |
| 网络 | 不需要外网；只用本机回环地址，端口由系统分配 |

测试用临时目录，并通过 `LocalAppDataDirectory` 覆盖，**不会写真实的 `%LOCALAPPDATA%` 和你的安装目录**（端到端 S1 还会专门断言这一点）。

| `tests/SmartUpdater.Packer.Tests` | 352 | 打包与签名引擎、preserve 匹配、同一输入逐字节相同的打包、往返测试（打包 → 客户端可读） |

### 3.2 常用命令

```powershell
# 全部（推荐带上防卡死超时）
dotnet build -c Release --no-incremental
dotnet test  -c Release --no-build --blame-hang-timeout 120s

# 只跑一个项目
dotnet test tests\SmartUpdater.Tests -c Release --no-build

# 只跑名字里含某个词的测试
dotnet test tests\SmartUpdater.Tests -c Release --no-build --filter "FullyQualifiedName~PackageApplier"
```

### 3.3 要注意

- 项目开启了 `TreatWarningsAsErrors`，**有警告就等于构建失败**。
- 测试不会调用 `SmartUpdaterApp.Run`，不会弹窗。
- 测试失败**不要**通过改断言、加 `Skip` 或放宽阈值来"变绿"，先找出真正的原因。
- 个别测试偶发失败时，先重跑一次；**同一个测试稳定失败才是真问题**。偶发失败请保存报错原文（见 §7）。

## 4. 端到端（e2e）

### 4.1 怎么跑

```powershell
# 全部场景
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\e2e\run-e2e.ps1

# 只跑 S1，并保留产物（截图、日志、安装目录）方便看
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\e2e\run-e2e.ps1 -Scenario S1 -KeepArtifacts
```

脚本会扫描 `tools\e2e\scenarios\s*.ps1`，按文件名顺序执行。

| 场景 | 内容 |
|---|---|
| `S0` | 脚本框架自检 |
| `S0B` | 发布与打包步骤自检 |
| `S0C` | 模拟服务器起停与控制接口自检 |
| `S0D` | 断言库自检 |
| **`S1`** | **真实升级：可选更新，用户点"现在更新"（1.0.0 → 1.1.0）** |

> 打包步骤经由 `tools\e2e\PackerHost`：Packer 只有图形界面，脚本没法带参数调用它，所以用这个小程序把命令行交给 Packer 里的打包 / 签名引擎并原样返回退出码。它只服务端到端脚本，不进解决方案，不对外发布。

### 4.2 S1 做了什么

1. 发布并打包 1.0.0 与 1.1.0。1.1.0 相对 1.0.0：**改了** `appsettings.json`（设为 preserve）、**删了** `THIRD-PARTY-NOTICES.txt`、**加了** `release-notes.txt`。
2. 启动模拟服务器，安装 1.0.0，并把 `appsettings.json` 改成"用户自己的内容"。
3. 启动示例程序；它弹出"可选更新"窗口，钩子自动回答"现在更新"。
4. 等旧进程退出，新进程（不同 PID）报告已启动，版本为 1.1.0.0、从 1.0.0.0 更新而来。

**全部满足才算 PASS：**

- 安装目录与 1.1.0 的发布物一致，**唯独 `appsettings.json` 保留用户内容**。
- 新增的文件存在，被删除的文件消失。
- 没有残留的 `.sunew` / `.suold`；更新日志已收敛；`state.json` 版本为 1.1.0.0；下载缓存已清空。
- 没有写到真实的 `%LOCALAPPDATA%`。
- 模拟服务器恰好收到 1 条 `Updated` 上报（1.0.0.0 → 1.1.0.0，成功）。
- 本地滚动日志能还原整个过程。
- 事件处理器从未在非界面线程上执行。
- 三张截图存在且有效：`01-before.png`（升级前）、`02-modal.png`（更新弹窗）、`03-after.png`（升级后）。

### 4.3 结果和产物

- **成功**：`PASS S1 optional update accepted (约 20s)`，退出码 0。
- **失败**：退出码 1，详细报告在 `tools\e2e\e2e-report.txt`。
- 加 `-KeepArtifacts` 会打印 `artifacts kept at <目录>`（在 `%TEMP%\smartupdater-e2e-<随机串>` 下），里面有截图、`events.log` 和安装目录。
- 每个场景结束后脚本会清理它启动的所有进程；清理不掉的进程会让该场景判 FAIL。临时目录删不掉（杀毒软件占用等）只是一条 `WARN`，不影响结论。

### 4.4 注意

- 运行时屏幕上会短暂出现示例窗口，**不要手动点击**，否则会干扰自动应答。
- 不要同时开多份 e2e，会争抢 CPU 和杀毒软件扫描。
- 不要用 `taskkill /IM` 按名字杀进程（会误杀别的程序），只按 PID 结束。

## 7. 当前覆盖情况与已知缺口

**已验证**
- 构建 0 警告 0 错误；4 个测试项目共 1811 个测试全部通过。
- 客户端端到端集成测试（本机回环服务器）：完整往返、包哈希损坏被拒绝并清理下载文件等。
- 端到端：`S0`、`S0B`、`S0C`、`S0D`、`S1` 全部 PASS。
- AOT 原生发布无 `ILxxxx` 诊断，原生程序输出 `AOT-SMOKE OK`。
- NuGet 包里没有 `.exe`。

**尚未完成 / 未验证**
- **真实端到端场景目前只有 S1。** 回滚、强制更新、灰度、签名、断点续传、断网、崩溃恢复的端到端脚本还没写；它们的核心逻辑有单元和集成测试覆盖，但没有"真实进程 + 真实窗口"的验证。
- 示例程序的 `Program` / `MainWindow` / `UpdateDriver` 只由 S1 覆盖；`Preheat`（启动早期预加载程序集）**没有任何自动化测试**。
- 已知的设计局限：更新提交过程被中断后再次崩溃的极端序列，可能静默回到较旧的文件集（消除它需要增加提交进度日志，会改动协议）；读取 `state.json` 失败（如被占用）时，本次会使用内存里新生成的设备标识，且不覆盖原文件。
- Packer 写文件（`releases.json`、zip）**没有重试**，被杀毒软件等短暂占用时可能失败并以退出码 4 结束。
- Packer 图形界面的中文字体和文件对话框没有截图确认。
- **偶发失败，原因未查明**：崩溃恢复类测试（`UpdateRecoveryTests`）在整个解决方案并行运行、且刚重新构建后的第一次运行时，可能偶发单个用例失败（已观察到的是 `Done_recovery_survives_a_crash_at_any_step_and_converges_on_rerun` 和 `Done_writes_state_first_and_deletes_the_journal_last`）；单项目重跑、并发压测（含 60 次并发）、反复重新构建后立刻再跑，均未复现。出现时请先保存完整报错。

## 8. 附：模拟服务器 `MockServer`（联调与故障注入）

`samples/MockServer` 是一个模拟生产环境的服务器，用来构造各种场景。它**只用 ASP.NET Core 共享框架**，不引入任何 NuGet 包；`releases.json` 与 `packages/` 交给静态文件中间件托管，所以 **ETag、`If-None-Match` → 304、`Range` 断点续传都是框架原生行为**——测 ETag 轮询时，测的是真实的 HTTP 语义。

### 启动

```powershell
dotnet run --project samples/MockServer -- --root .\releases --port 0
# 第一行输出：LISTENING http://127.0.0.1:<端口>/   ← 这就是服务器地址
```

命令行只有两个选项：`--root <目录>`（必填，目录必须已存在）和 `--port <n>`（默认 0，取值 0..65535；0 表示由系统分配端口）。

### 手动试一遍

`--root` 目录里放一个 `releases.json`，然后（把 `<地址>` 换成上面输出的地址）：

```powershell
Invoke-WebRequest <地址>/releases.json                     # 200，带 ETag
Invoke-RestMethod -Method Post <地址>/_control/faults -ContentType application/json `
  -Body '{"path":"/releases.json","status":503,"retryAfterSeconds":30}'
Invoke-WebRequest <地址>/releases.json                     # 503，带 Retry-After: 30
Invoke-RestMethod -Method Delete <地址>/_control/faults     # 清除故障，再请求恢复 200
```

带上 `If-None-Match: <ETag>` 再请求同一个文件，应返回 304。

### 控制接口

路径前缀固定为 `/_control/`，用于故障注入和运行中改配置：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/_control/faults` | `{"path":"/releases.json","status":503,"retryAfterSeconds":30,"failCount":2}`；`failCount` = 前 N 次失败之后成功 |
| `DELETE` | `/_control/faults` | 清空故障 |
| `POST` | `/_control/transfer` | `{"path":"/packages/MyApp-1.2.4.zip","bytesPerSecond":65536,"cutAfterBytes":1048576}`，限速与中途断流 |
| `DELETE` | `/_control/transfer` | 清空 |
| `POST` | `/_control/feed-overlay` | 在内存里改写 feed：`{"body":"…"}` 给畸形 JSON，或 `{"version":"1.2.4","rolloutPercent":5,"mode":"mandatory","packageSha256":"dead","schemaVersion":99,"client":{…}}` |
| `DELETE` | `/_control/feed-overlay` | 撤销改写 |
| `GET` | `/_control/reports` | 读回收到的上报 |
| `DELETE` | `/_control/reports` | 清空上报 |
| `POST` | `/_control/reset` | 一次清空全部状态 |

**改写只改内存，磁盘文件一字不动**，而且每次改写都会推进文件的最后修改时间——否则内容长度相同的两次改写会算出同一个 ETag，客户端会一直收到 304，永远看不到新下发的配置。

上报接口 `POST /api/v1/update-reports` 返回 `202 Accepted`，把收到的报文原样存在内存里，并单行打印到控制台（`REPORT <eventType> <json>`），可用 `GET /_control/reports` 读回。

## 9. 出问题时怎么排查

| 现象 | 排查 |
|---|---|
| `dotnet test` 偶发失败 | 重跑一次；稳定复现才是真问题；偶发时保存完整报错（见 §7） |
| S1 超时 | 加 `-KeepArtifacts`，看保留目录里的 `events.log` 和 `.smartupdater\logs\` |
| S1 看不到窗口 | 桌面会话被锁屏或远程断开，会导致无法渲染和截图 |
| e2e 报"临时目录删不掉"的 `WARN` | 杀毒软件短暂占用，不影响结论；可手动删 `%TEMP%\smartupdater-e2e-*` |
| AOT 冒烟失败 | 看脚本最后打印的日志路径；先确认已装 Visual Studio 的 C++ 桌面开发工作负载 |
| 有遗留的示例 / 模拟服务器进程 | 只按 PID 结束；e2e 正常情况下会自动清理 |
