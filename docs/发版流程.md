> **一键发版**：在 Claude Code 里输入 `/one-release X.Y.Z`，定版、验绿、合并、打标签、发包、核对全部自动完成，流程见 `.claude/skills/one-release/SKILL.md`。下面是它背后的各个步骤。

# 发版流程

**推一个 `v*` 标签就发包，之后全自动。** 包版本取自标签，不用改任何文件里的版本号。

## 发一个版本

1. 在 `dev` 上把 `CHANGELOG.md` 里 `[Unreleased]` 的条目移到新的 `## [X.Y.Z] - 日期` 段落，推送，等 CI 变绿。
2. `dev` 推送后由 `auto-merge` 工作流自动开 PR 并启用 auto-merge，`build-test` 变绿后自动合并进 `main`，不需要人工操作。合并后在本地 `git pull origin main` 同步 `dev`。
3. 在 `main` 上打标签并推送：

   ```powershell
   git switch main
   git pull
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

标签一推，`.github/workflows/release.yml` 自动执行：

| 步骤 | 内容 |
|---|---|
| verify | 标签必须在 `main` 上；标签必须是 `vX.Y.Z` 或 `vX.Y.Z-预发布` 格式；用标签的版本号构建、跑全部测试、检查包内没有 `.exe`、打包 |
| publish | verify 全绿才执行：经 Trusted Publishing 推送到 nuget.org（含符号包），并建 GitHub Release，说明取自 CHANGELOG 对应段落 |

verify 红了不会发包，此时删标签修完再打：`git tag -d vX.Y.Z` 然后 `git push origin :refs/tags/vX.Y.Z`。
**已经发到 nuget.org 的版本不能撤回**，只能下架（unlist）再发修订版。publish 中途失败可以直接重跑该 job，已发的版本会被跳过。

版本号规则见 `CHANGELOG.md` 开头。

## 一次性配置（只做一次）

1. **nuget.org**：Trusted Publishing 策略，Repository Owner = `SimpleOne-X`，Repository = `SmartUpdater`，Workflow File = `release.yml`。仓库里不需要保存任何 API Key。
2. **GitHub 分支规则**：`main` 要求状态检查 `build-test` 通过、禁止强推、禁止删除；`dev` 禁止强推、禁止删除。
3. 如果 nuget.org 用户名不是 `Andy_Zhong`，在仓库变量里设置 `NUGET_USER`。
