# 使用手册

让你的 Windows 程序**自己检查、下载、安装新版本并重启**。

这份手册分两部分，按你的角色看就行：

- **写程序的人**：看[第 2 章](#2-接入程序写程序的人一次性)，把更新功能加进你的程序，只做一次。
- **发新版本的人**：看[第 3 章](#3-发新版本发布的人每次)，每次发版照着做。

---

## 1. 它是怎么运转的

```
你发版                           你的服务器                        用户的电脑
────────                      ──────────────                   ──────────────────
publish 出新版本  →  打包工具  →  releases.json  ←──定期来看──  你的程序（已接入本包）
                     生成升级包    packages/xxx.zip  ──下载──→   校验 → 替换自己 → 重启
```

几个词：

| 词 | 意思 |
|---|---|
| **升级包** | 一个 zip 文件，里面是新版本的全部文件 |
| **releases.json** | "新版本清单"：最新版本号、升级包在哪、更新说明。用户的程序每隔一会儿来看一眼 |
| **发布目录（releases）** | 装着 `releases.json` 和升级包的文件夹，最后整个放到服务器上 |
| **签名** | 给清单盖"防伪章"，防止别人冒充你发假更新。可选，强烈建议 |

**前提**：程序要装在**当前用户能写入的目录**（推荐 `%LOCALAPPDATA%\你的程序\`）。装在 `Program Files` 下，更新功能会自动关闭，程序照常运行、不报错。

## 2. 接入程序（写程序的人，一次性）

### 2.1 安装

```powershell
dotnet add package SimpleOneX.SmartUpdater
```

所有公开类型都在命名空间 `SimpleOneX.SmartUpdater` 下。

### 2.2 改 `Main`

```csharp
using SimpleOneX.SmartUpdater;

[STAThread]
static void Main(string[] args)              // ① 必须接收 args
{
    // ② 必须是 Main 的第一句，先于任何界面初始化和单实例检查
    StartupResult startup = SmartUpdaterApp.Run(args);

    // ③ 单实例：已有一个在运行就通知它，自己退出。用 using，不要自己 ReleaseMutex
    using SingleInstanceHandle? instance = startup.TryAcquireSingleInstance("MyApp");
    if (instance is null)
    {
        SmartUpdaterApp.ActivateExistingInstance();
        return;
    }

    // ④ 之后才是你自己的启动代码
    ApplicationConfiguration.Initialize();
    Application.Run(new MainForm(startup));
}
```

`SmartUpdaterApp.Run` 负责"更新后重启"的交接和崩溃恢复，返回的 `StartupResult` 有：

| 属性 | 含义 |
|---|---|
| `JustUpdated` / `FromVersion` / `ToVersion` | 这次启动是否刚更新完，从哪个版本到哪个版本 |
| `CurrentVersion` | 当前版本 |
| `IsUpdateEnabled` / `UpdateDisabledReason` | 更新功能是否可用；不可用时的原因（如安装目录不可写） |
| `IsRollbackApplied` | 上次更新失败后是否发生了回滚 |

另一个实例调用 `ActivateExistingInstance()` 时，`instance.ActivationRequested` 事件会触发（在线程池线程上），怎么把窗口带到前台由你决定，记得切回界面线程。

### 2.3 启动更新

最简单的写法，指向服务器上的 `releases.json`：

```csharp
await new UpdateClient("https://你的服务器/updates/releases.json").RunAsync();
```

放在主窗口里，并且**返回就关闭窗口**：

```csharp
private readonly CancellationTokenSource _cts = new();

protected override async void OnShown(EventArgs e)
{
    var client = new UpdateClient("https://你的服务器/updates/releases.json");
    try   { await client.RunAsync(_cts.Token); Close(); }   // 新版本已启动，本进程退出
    catch (OperationCanceledException) { }                   // 你自己取消了
}
```

`RunAsync` 的行为：

- 定期检查新版本，发现后下载、校验、安装。
- **只有新版本进程已经启动后才会返回**——返回就该退出你的程序。
- 取消会抛 `OperationCanceledException`；关闭窗口前先取消它。
- 安装目录不可写时**不会返回**，只做心跳上报，程序正常使用。

需要更多设置时，用 `UpdateClientOptions`：

```csharp
var client = new UpdateClient(new UpdateClientOptions
{
    FeedUrl   = "https://你的服务器/updates/releases.json",
    ReportUrl = "https://你的服务器/api/v1/update-reports",   // 可选：上报更新结果
    PublicKey = "<签名时显示的公钥>",                          // 可选：启用验签
    LogCallback = (level, message, ex) => Debug.WriteLine($"[{level}] {message}"),
});
```

常用选项：

| 选项 | 默认 | 说明 |
|---|---|---|
| `FeedUrl` | 必填（或用 `Feed` 自带实现） | `releases.json` 的地址 |
| `ReportUrl` | 不上报 | 上报地址 |
| `PublicKey` | 不验签 | ECDSA P-256 公钥（签名时显示的那串） |
| `PollInterval` | 5 分钟 | 检查间隔，限制在 1 分钟 ~ 1 天；服务器 `releases.json` 里下发的值优先 |
| `ShutdownTimeout` | 15 秒 | 重启前等你收尾的时间（最多 10 分钟） |
| `AllowVersionDowngrade` | 否 | 是否允许更新到更低的版本 |
| `EnableFileLogging` | 是 | 写滚动日志文件 |
| `LogCallback` | 无 | 把日志接到你自己的日志系统 |

### 2.4 让用户决定要不要更新

"可选更新"时，订阅 `UpdateAvailable`；**不订阅就自动更新**。事件已经切回界面线程，不需要自己 `Invoke`：

```csharp
client.UpdateAvailable += (s, e) =>
{
    var answer = MessageBox.Show(
        $"发现新版本 {e.Version.ToString(3)}（当前 {e.CurrentVersion.ToString(3)}）\n{e.Notes}\n\n现在更新？",
        "更新", MessageBoxButtons.YesNoCancel);

    if (answer == DialogResult.Yes)      e.Accept();      // 现在更新
    else if (answer == DialogResult.No)  e.Postpone();    // 稍后再问（下次启动再问）
    else                                 e.Skip();        // 跳过这个版本
};
```

"强制更新"不会走到这里，直接下载安装。其他事件：

```csharp
client.ProgressChanged += (s, e) => progressBar.Value = (int)e.Percent;   // 下载进度

client.Restarting += (s, e) =>
{
    // 新版本即将接管：把你的收尾任务交给包等待（最多等 ShutdownTimeout）
    e.WaitFor(workLoopTask);
};

client.Failed += (s, e) => ShowError($"更新失败（{e.Stage}）：{e.Exception.Message}");
```

### 2.5 更新后提示一下

```csharp
if (startup.JustUpdated)
    statusBar.Text = $"已从 {startup.FromVersion?.ToString(3)} 更新到 {startup.ToVersion?.ToString(3)}";
```

建议放状态栏，别弹窗打断用户。

### 2.6 接入自查

1. `Main(string[] args)`，`SmartUpdaterApp.Run(args)` 是第一句。
2. 单实例用 `using SingleInstanceHandle?`，代码里没有 `ReleaseMutex`。
3. 有一个可取消的工作循环，并在 `Restarting` 里 `e.WaitFor(task)`。
4. 可选更新时自己弹窗（订阅 `UpdateAvailable`），不然会自动更新。
5. 不要自己保存设备标识，也不要自己维护"正在更新"的跨进程标志，这些由包管理。
6. 你的程序若有自己的 `JsonSerializerContext`，不要把包里的更新类型放进去。
7. 非 AOT 发布时，替换完成到进程退出之间若加载了此前没加载过的程序集，会加载到新版本的 DLL。启动早期先把关键程序集加载一遍（示例见 `samples/MinimalApp.WinForms/Preheat.cs`）。
8. 自启项指向安装目录里的主程序。

## 3. 发新版本（发布的人，每次）

整个过程四步：**publish → 打包 →（签名）→ 上传**。

### 3.0 第一次使用前（只做一次）

1. 电脑装好 **.NET 10 SDK**（能运行 `dotnet`）。
2. 如果要签名，生成一对钥匙（得到的 `private.pem` 就是**私钥**）：

   ```powershell
   openssl ecparam -name prime256v1 -genkey -noout -out private.pem
   ```

   Windows 上可以用 Git for Windows 自带的 `C:\Program Files\Git\usr\bin\openssl.exe`。

   > 私钥要像银行卡密码一样保管：不发给别人、不上传到代码仓库、不放在公共电脑上。丢了或泄露，就得换钥匙、重新发版。

### 3.1 publish 出新版本

```powershell
dotnet publish MyApp -c Release -o .\publish
```

### 3.2 打开打包工具

在 SmartUpdater 项目目录下：

```powershell
dotnet run -c Release --project tools\SmartUpdater.Packer
```

弹出"SmartUpdater 打包工具"窗口：上半部分是**打包**，下半部分是**签名**，最底下是**日志**（做了什么、成没成功都显示在这里，出错时看这里）。

### 3.3 打包

| 界面上的字段 | 怎么填 | 必填？ |
|---|---|---|
| 应用目录 | 点"浏览…"，选上一步的 `publish` 文件夹 | 必填 |
| 输出目录 | 选一个放结果的文件夹，如 `releases`（不存在会自动创建） | 必填 |
| 版本号（四段） | 新版本号，如 `1.2.4.0`，**必须比用户现在的版本高** | 必填 |
| 包名前缀 | 升级包文件名的开头，如 `MyApp`；不填就用主程序的名字 | 可选 |
| 渠道 | 一般不用管，默认 `stable` | 可选 |
| 灰度百分比 | 先让一部分用户试用就填 `5`（5% 的用户）；不填是 100% | 可选 |
| 最低可升级版本 | 太老的版本必须先升到中间版本时才填，一般留空 | 可选 |
| 更新说明 | 给用户看的一两句话 | 可选 |
| preserve（每行一个） | **升级时不要覆盖的文件**，见下 | 可选 |

窗口里的勾选项：**强制更新（mandatory）**——不勾：用户的程序弹窗询问，用户可以跳过；勾上：检测到就直接更新，不问用户。**只在必须修复严重问题时才勾。**

**preserve**：用户机器上有些文件是他自己的（配置、数据），升级时不能被覆盖。一行写一个：

```
appsettings.json
data/**
```

第一行保留 `appsettings.json`，第二行保留 `data` 文件夹里的所有东西。`*` 代表任意字符，`**` 代表任意多层文件夹；不支持 `[]` 和 `{}`，写了会报错。

点 **"生成升级包 (pack)"**，日志里出现成功提示就完成了。输出目录里会有：

```
releases\
├── releases.json              ← 新版本清单
└── packages\
    └── MyApp-1.2.4.zip        ← 升级包
```

### 3.4 签名（可选，建议做）

| 界面上的字段 | 怎么填 |
|---|---|
| releases.json | 选上一步生成的 `releases\releases.json` |
| 私钥文件 (PEM) | 选你的 `private.pem` |

点 **"签名 (sign)"**，日志里会显示一串**公钥**。

- **第一次签名**：把这串公钥交给写程序的人，填到程序的 `UpdateClientOptions.PublicKey`。以后程序只认盖过章的更新。
- **之后每次发版**只要重新签名，公钥不变，程序不用改。
- "重签已有签名的条目"平时**不用勾**。

> 顺序必须是**先打包、后签名**。签完不要再手工改 `releases.json`，改了签名就作废。

### 3.5 上传到服务器

把 `releases` 文件夹里的东西放到服务器上。

> **先传 `packages` 文件夹，最后再传 `releases.json`。** 清单是入口，最后更新它，用户才不会看到"清单说有新版本，升级包却还没传完"。

上传完成，用户的程序下次检查时就会发现新版本。

**发版前自查**：版本号比上一版高 · 要保留的文件已写进 preserve · 没有误勾"强制更新" · 已签名且之后没手工改过 `releases.json` · 先传 `packages` 后传 `releases.json` · 私钥没有上传到公开的地方。

## 4. 服务器怎么放

把 `releases` 目录放到任何能提供静态文件的地方即可：Nginx、IIS、OSS，或者局域网共享目录（UNC）。要求：

- 支持 `ETag` / `If-None-Match`（程序用它做轻量检查，返回 304 表示没有变化）；
- 最好支持 `Range`（断点续传）；
- 用 HTTPS。走共享目录（UNC）时没有 TLS 保护，**务必先开签名**；
- 可选：提供 `POST /api/v1/update-reports`（返回 `202`）接收更新结果。不需要就不设 `ReportUrl`。

**想在自己电脑上试一遍整个流程**：

```powershell
dotnet run --project samples/MockServer -- --root .\releases --port 0
# 第一行输出：LISTENING http://127.0.0.1:<端口>/  ← 这就是服务器地址
```

## 5. 常用操作

| 我想…… | 怎么做 |
|---|---|
| 先让少量用户试用 | 灰度百分比填 `5` 发布；没问题后勾"强制替换同版本条目"，把灰度改成 `100`（或留空），重新打包并重新签名 |
| 必须让所有人立刻更新 | 勾"强制更新（mandatory）" |
| 让用户的设置不丢 | 把配置文件写进 preserve |
| 同一个版本号发错了要重发 | 勾"强制替换同版本条目"再打包；旧签名会作废，**必须重新签名** |
| 撤回一个有问题的版本 | 从服务器的 `releases.json` 里删掉那个版本的条目再上传。已经升级的用户不会自动退回旧版（回退到低版本需要程序开启 `AllowVersionDowngrade`，这个流程还没有端到端验证） |
| 启用防伪 | 发布时签名，程序里把公钥填到 `PublicKey` |

## 6. 出错了怎么办

先看打包工具窗口最底下的**日志**，它会用中文告诉你哪里填错了。

| 现象 | 可能的原因 |
|---|---|
| 日志说"未执行：……" | 有必填项没填，或格式不对（如版本号写成 `abc`），按提示改 |
| 提示同版本已存在 | 这个版本号已经打过包而且内容不同。想覆盖就勾"强制替换同版本条目"，否则换更高的版本号 |
| 签名失败 | 私钥选错了，或不是按上面的 `openssl` 命令生成的 |
| 程序报"验签失败" | 程序里的公钥和签名用的私钥不成对；或签名之后手工改过 `releases.json`（改了要重新签名） |
| 用户没收到更新 | ① 版本号不比用户当前的高；② 灰度没轮到他；③ 他点过"跳过此版本"；④ 清单或升级包没传到服务器，或传的顺序反了；⑤ 程序装在 `Program Files` 下，更新被关闭——查 `startup.IsUpdateEnabled` 与 `UpdateDisabledReason` |
| 弹窗没出现 | 那个版本是"强制更新"（不询问）；或用户已跳过；或灰度没轮到 |
| 更新后加载到新旧混合的 DLL | 非 AOT 发布的延迟加载窗口，见 2.6 第 7 条 |
| 想看程序里发生了什么 | 设置 `LogCallback`，或看安装目录下 `.smartupdater\logs\` 的滚动日志 |

**用户机器上的文件**：

| 位置 | 内容 |
|---|---|
| `<安装目录>\.smartupdater\` | 状态、日志、上报队列、更新日志（journal） |
| `%LOCALAPPDATA%\…` | 下载缓存、日志回退目录 |
| `*.sunew` / `*.suold` | 更新过程中的临时文件，正常完成后不应残留 |

**手工恢复**：极端情况下（断电恰好发生在主程序换名的极短瞬间）程序起不来，把安装目录下所有 `*.suold` 改回原名即可。这只保证旧文件全部回到原位；这次更新新增的文件没有对应的 `.suold`，会留在原地。

## 7. 限制

- 仅 Windows；包目标框架为 `net10.0`。
- 全程不提权：需要管理员权限才能写入的安装目录不支持。
- 目前有真实端到端验证的场景是"可选更新，用户点现在更新"。回滚、强制更新、灰度、签名、断点续传等场景的端到端脚本尚未完成，它们的核心逻辑有单元和集成测试覆盖，详见《测试文档》。
